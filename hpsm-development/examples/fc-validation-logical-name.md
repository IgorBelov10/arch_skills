# Пример: FC-валидация обязательности и формата поля

**Задача:** поле `logical.name` объекта `device` должно быть обязательным и не содержать пробелов.

**Where:** Format Control запись для `device`, панель Validations.

| Колонка | Значение |
|---|---|
| Add | `true` |
| Update | `true` |
| Validation | `not(null(logical.name)) and index(rtrim(logical.name)," ")=0` |
| Msg | `Logical Name обязателен для заполнения и не должен содержать пробелов` |
| Focus | `logical.name` |

**Разбор паттерна для аналогичных задач:**
- Обязательность поля: `not(null(имя.поля))`
- Отсутствие пробелов: `index(rtrim(имя.поля)," ")=0`
- Ограничение длины: добавить `and lng(имя.поля)<=N`
- Условия Add/Update можно сузить (например, только Add, если поле нельзя менять после создания) — не копировать `true`/`true` бездумно, если бизнес-логика требует иного.

См. `references/format-control.md` для полной структуры FC и предупреждения про проверку уникальности значения (там отдельно про self-exclusion, не решено "универсальной" формулой).
