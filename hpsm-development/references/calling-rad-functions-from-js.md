# Вызов RAD-функций (`system.functions.*`) из JS — предпочитай их встроенным JS-объектам

## Подтверждённый механизм вызова RAD-функции из JS

Источник: обсуждение на community.microfocus/opentext (не выдумано). Чтобы вызвать RAD-функцию из JS-кода в SM, обращаешься к ней через `system.functions.<имя>(...)`.

Если имя самой RAD-функции содержит точки (составное имя, например `simple.file.load`), точки при вызове из JS заменяются на подчёркивания:
```javascript
system.functions.simple_file_load(pathToFile, targetFileName, dropFlag);
```

Для RAD-функций с простым (не составным) именем — вызов без всяких переименований, просто `system.functions.<имя>(...)`. Например, RAD-функции длины строки, обрезки пробелов и т.п. из `rad-language.md` (`lng`, `rtrim`, `ltrim`, `index`, `substr` и другие) вызываются из JS так:
```javascript
system.functions.lng(someString);
system.functions.rtrim(someString);
system.functions.index(someString, "подстрока");
```

**`funcs`** здесь — не часть имени функции и не namespace-префикс, а место, где хранятся определения самих RAD-функций (встроенных и кастомных) на инстансе. Вызов из JS не зависит от того, что функция лежит в `funcs`, — используется всегда просто `system.functions.<имя_функции>`.

## Главное правило: предпочитай существующую RAD-функцию вместо реализации той же логики через встроенные JS-объекты

Если для нужной операции уже есть готовая RAD-функция (встроенная, из `rad-language.md`, или кастомная для этого инстанса) — **вызови её через `system.functions.<имя>(...)`**, а не переписывай ту же логику через встроенные JS-объекты (`String`, `Date`, `Math` и т.д.), даже если встроенный JS-эквивалент кажется проще или очевиднее.

Почему это важно, а не просто стилистическое предпочтение:
- RAD-функции (особенно кастомные) часто уже учитывают специфику/бизнес-правила конкретного инстанса (особый формат, локаль, edge-cases), которых обычный встроенный JS-метод не знает.
- Единообразие с остальным кодом организации упрощает сопровождение — если весь код использует одну и ту же RAD-функцию для типовой операции, а сгенерированный код внезапно использует голый JS для того же самого, это создаёт два разных пути с потенциально разным поведением на одних и тех же данных.

## Как действовать, если не уверен, что нужная RAD-функция вообще существует

1. Проверь код, который прислал пользователь, — используется ли там уже `system.functions.<что-то>` для похожей задачи.
2. Если это встроенная RAD-функция общего назначения — сверься с `references/rad-language.md`.
3. Если не видно ни там, ни там — спроси пользователя напрямую, есть ли готовая RAD-функция для этой операции, прежде чем писать код с нуля через встроенные JS-объекты.
4. Не изобретай имена RAD-функций по аналогии ("раз есть X, то наверняка есть и Y") — называние по аналогии не подтверждает существование конкретной функции.
