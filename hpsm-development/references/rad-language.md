# RAD-язык — базовые сведения

RAD (Rapid Application Development language) — исторический язык SM, предшествующий поддержке JS. До сих пор используется в Format Control, панелях процессов, некоторых системных выражениях. Синтаксис отличается от JS — не путать одно с другим и не пытаться писать RAD-выражение в JS-синтаксисе или наоборот.

## Переменные

- `имя.поля` — поле текущей записи (контекст зависит от того, где выполняется выражение).
- `$file`, `$fileN` — записи, полученные через дополнительные запросы (Additional File Queries в FC, аналогично в других механизмах).
- `$L.file` — поля текущей редактируемой/обрабатываемой записи (используется, когда нужно явно отличить "текущую запись" от результата запроса).
- `$G.*` — глобальные переменные сессии/системы (например, признаки прав пользователя, ESS-режим и т.п. — конкретный набор кастомный).

## Часто встречающиеся функции (подтверждено использование в реальных FC-примерах)

| Функция | Смысл |
|---|---|
| `null(x)` | true, если значение пустое |
| `not(x)` | логическое отрицание |
| `index(строка, подстрока)` | позиция вхождения подстроки; `0`, если не найдено |
| `rtrim(строка)` / `ltrim(строка)` | обрезка пробелов справа/слева |
| `lng(строка)` | длина строки |
| `substr(строка, начало, длина)` | подстрока |
| `in` | оператор проверки принадлежности/поиска в файле, например `logical.name=logical.name in $file` |

Список здесь — только то, что использовалось в примерах, разобранных в этом skill. **Полный официальный список всех RAD-функций** — в `references/rad-functions-list.md`; загляни туда, прежде чем реализовывать что-то с нуля через встроенные JS-объекты — вероятно, готовая RAD-функция уже есть.

## Условия Add/Update/Delete/Display

Во многих RAD-механизмах (не только FC) встречается одна и та же идея: 4 отдельных условия, определяющих, **при каком действии над записью** сработает данное правило:

- `Add` — при создании новой записи
- `Update` — при изменении существующей
- `Delete` — при удалении
- `Display` — при открытии/отображении записи (без изменения)

Каждое из них — RAD-выражение, возвращающее true/false. Пустое значение обычно трактуется как "не выполняется для этого действия" (не как "всегда true").

## Коды возврата (RC-коды)

Многие встроенные функции работы с записями (что в RAD, что в JS-обёртках вроде `SCFile`) возвращают код результата вместо/вместе с исключением:

- `RC_SUCCESS` — операция успешна
- иные `RC_*` константы — различные классы ошибок/особых случаев (например "запись не найдена", "нет прав", конфликт блокировки и т.д.)

**Важно:** не полагайся только на try/catch при работе с SM API — многие ошибки приходят как код возврата, а не как брошенное исключение. Всегда проверяй код возврата явно после операций чтения/записи, если функция его возвращает.
