# JS API внутри HPSM

SM поддерживает серверный JS (движок на базе Rhino в старых версиях) как альтернативу RAD для ScriptLibrary. У него есть собственные встроенные классы для доступа к данным — это не Node.js и не браузерный JS, стандартные web/npm-библиотеки недоступны.

## SCFile — основной класс для работы с записями (подтверждено официальной документацией)

```javascript
var deviceFile = new SCFile("device");          // открыть "файл" (объект/таблицу)
var rc = deviceFile.doSelect("status=\"Active\""); // выборка по условию, синтаксис условия — как в RAD-запросах

if (rc == RC_SUCCESS) {
    // deviceFile теперь содержит первую найденную запись
    deviceFile.setFields("some.field", someValue);
    var updateRc = deviceFile.doUpdate();

    rc = deviceFile.getNext(); // перейти к следующей записи в выборке
}
```

Ключевые методы (существуют и задокументированы у Micro Focus):
- `doSelect(query)` — выборка по условию
- `getFirst()` / `getNext()` / `getPrev()` / `getLast()` — навигация по выборке
- `doUpdate()` — сохранить изменения текущей записи
- `doInsert()` — создать новую запись
- `doRemove()` / `doAction()` / `doSave()` — прочие операции над записью (доступность/точное поведение может отличаться по версии — если сомневаешься, ищи пример использования в коде клиента)
- `setFields(имя, значение)` — установить значение поля
- `setOrderBy(...)` — задать сортировку выборки
- `getLastRC()` — код последней операции
- `getMessages()` — текстовые сообщения/ошибки, накопленные объектом
- `isRecord()` — проверка, что текущий объект содержит валидную запись

## Логирование и вывод — используй `print()`, не `lib.logmessage`

**Подтверждено на практике на этом инстансе:** `lib.logmessage(...)` — несуществующая/нерабочая функция здесь, несмотря на то что она часто встречается в общих примерах HPSM. **Используй `print(сообщение)`** — это единственный подтверждённый на этом инстансе способ вывода (уже использовался и работал в скрипте дампа dbdict). Все примеры в этом skill должны выводить через `print()`, а не через `lib.logmessage`.

Если нужно различать уровни (INFO/ERROR/WARN) — просто включай это текстом в само сообщение, например `print("ERROR: " + текст)`, отдельного механизма уровней логирования не подтверждено.

## Вызов ScriptLibrary

`system.library.<scriptname>.<functionname>(...)` — вызов функции, объявленной в другой ScriptLibrary-записи.

## REST/HTTP-вызовы наружу из SM

**Осторожно:** в этом skill сознательно нет "универсальной" готовой функции вызова внешнего REST API (`RunRestful` или аналог) — на разных инстансах она может быть кастомной ScriptLibrary-функцией, встроенным механизмом (Integration Manager/REST connector, настраиваемым через UI, а не JS), либо конвенцией именования (см. `references/scriptlibrary-and-triggers.md`). Прежде чем писать код исходящего REST-вызова — запроси реальный работающий пример такого вызова из этого инстанса.

## Особенности движка JS на этом инстансе (подтверждено на практике, не общее знание про SM)

Движок урезан относительно "полного" Rhino в паре конкретных мест — оба подтверждены реальным прогоном кода на этом инстансе, не догадка:
- Конструкция `for each (var x in ...)` **не работает** — использовать обычный индексный `for` (в т.ч. по `XMLList`, через `list[i]` + `.length()`).
- **Регулярное выражение литералом** (`/pattern/flags`) в месте вроде `str.replace(/.../,...)` **не принимается** — нужно сначала явно создать объект `new RegExp("pattern", "flags")` (с двойным экранированием обратного слэша в строке), и передавать уже его.
- **Не использовать JS-оператор `delete`** (`delete obj.prop`) — на этом инстансе он не подтверждён как безопасный/рабочий. Если нужно "убрать" свойство объекта — присваивай `null`/`undefined` вместо `delete`, если это по смыслу задачи достаточно; если нужно физически удалить запись/элемент — смотри предметный API (`SCFile.doRemove()` для записей, RAD-функция `delete` для массивов через `system.functions.delete(...)`, см. `references/rad-functions-list.md` — это RAD-функция с тем же именем, но другой вызов, не путать с JS-оператором).

Это не значит, что E4X/regex недоступны вообще — базовые объекты (`XML`, `RegExp`) работают, просто часть "облегчённого" синтаксиса вокруг них отключена. Если дальше встретится похожая ошибка на другой синтаксической конструкции — это тот же класс проблемы: движок ES-версии старше/уже, чем стандартный современный JS, пробуй эквивалент через явный конструктор объекта вместо литерала/сокращённого синтаксиса.

## Общее правило для этого файла

Всё, что перечислено выше как "подтверждено официальной документацией" — можно использовать с уверенностью. Всё, что помечено как "осторожно"/"по инстансу" — требует либо реального примера от пользователя, либо явного предупреждения в ответе, что это нужно протестировать.
