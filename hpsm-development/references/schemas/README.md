# references/schemas/ — реальные структуры таблиц (dbdict JSON)

## Что тут лежит

Файлы вида `<имя_таблицы>.json` — результат выполнения `DumpDbdictJson` (см. `examples/dump-dbdict-json.md`) на реальном инстансе SM. Это **подтверждённая, реальная структура конкретной таблицы** (поля, типы, ключи — как их сериализовал `SCFile.getXML()` для записи `dbdict`), а не общее описание "как обычно бывает".

## Как этим пользоваться (правило для модели)

Перед тем как писать код, который читает/пишет **конкретные имена полей** какого-либо объекта (`device`, `schedule`, `incidents` и т.д.):

1. Проверь, есть ли файл `references/schemas/<таблица>.json` для нужного объекта.
2. Если есть — **используй имена и типы полей оттуда**, а не из `references/objects.md` (там только общий, непроверенный набор полей "для ориентировки") и не из общих знаний о HPSM.
3. Если файла нет — веди себя как предписано в главном правиле `SKILL.md`: не изобретай имена полей, спроси у пользователя реальный пример или попроси прогнать `DumpDbdictJson` для этой таблицы.

## Формат содержимого

Структура JSON внутри каждого файла **не фиксирована жёстко** этим skill'ом — она ровно такая, какой её сериализовал `getXML()` на вашем инстансе (см. предупреждения в `examples/dump-dbdict-json.md` про то, что это не проверено на 100% на одном разборе). Смотри на файл как на факт, не пытайся подогнать его под какую-то ожидаемую заранее схему.
